# 🏋️ Workout Bot — Состояние проекта (Бортовой журнал)

## 1. Стек и архитектура
- **Язык:** Python 3.12
- **Фреймворк:** aiogram 3.x
- **БД:** PostgreSQL + SQLAlchemy 2.0 (asyncpg)
- **Архитектура:** 
  - `handlers/` — прием событий (разбиты по зонам: меню, подходы, таймеры, заметки, архивы).
  - `services/` — бизнес-логика и навигация (`training_service`, `navigation_service`).
  - `db/` — модели и запросы.
- **Правило импортов:** Всё в шапке файла, КРОМЕ импортов из соседних хэндлеров (делаются локально внутри функций во избежание циклических зависимостей).
- **Запуск:** Docker Compose (БД на порту 5433), `python bot.py`.

## 2. Ключевые сущности (БД)
- `User` — пользователи.
- `WorkoutType` — шаблоны тренировок (`is_archived` для архива, `is_in_rotation` для умной сортировки).
- `Exercise` — упражнения (`kind`: `strength`/`cardio`; `weight_kg`: **String** для текстовых весов; `is_optional`; `is_archived`).
- `WorkoutSession` — факт выполнения (`notes` для общей заметки к тренировке).
- `SessionSet` — выполненные подходы (`completed_at` для расчета отдыха).
- `SessionExerciseNote` — заметка к упражнению в конкретной сессии.

## 3. Архитектурные решения и паттерны (C1)
- **Время:** Храним в UTC, выводим в МСК (UTC+3).
- **Вес:** Строковый тип. Поддерживает «Своё тело», «Резинка», «10 кг».
- **Удаление:** Только мягкое (архивация) для сущностей с историей. Жесткое удаление — через двойное подтверждение в меню справочника.
- **Навигация (FSM):** Любой диалог пишет в `state` ключ `return_to` и `session_id` (или `ex_id`). `navigation_service.resolve_cancel_view()` возвращает пользователя на правильный экран.
- **Таймеры:** Разделены на два независимых (по ключам `session_id_list` и `session_id_ex_exid`). Уведомления разные. Автоудаление сообщений через 15 сек. Ввод через цифровую клавиатуру.
- **Умная сортировка:** Наверх списка поднимается тренировка, которую дольше всех не делали. Новые помечаются 🆕, тестовые можно убрать из ротации.
- **Опциональные:** Скрыты в папку. Если не сделаны — не портят прогресс. Если сделаны — подтягиваются в основной список на место по `sort_order`.
- **Заметки:** Показываются текущие и прошлые (с датой). Реализовано красивое копирование старых значений по тапу (тег `<code>`).
- **Цифровые клавиатуры:** Везде, где нужен ввод чисел (повторы, вес, время), используются inline-клавиатуры с кнопками `Готово`, `Стереть`, `Назад` и `Ввести текстом`.

## 4. Текущий статус (C1 ПОЛНОСТЬЮ ГОТОВ)
- Весь базовый функционал тренировок, справочника, таймеров и заметок работает.
- Интерфейс (UI/UX) отполирован: кнопки сгруппированы, ширина пузырей настроена, подсказки на месте.
- Настроены бэкапы (`.sql` дампы в папку `backups/`).

## 5. Roadmap (Что дальше)
- **C2 (История и Прогресс):** 
  - Просмотр прошлых тренировок (открыть и увидеть все подходы/заметки).
  - Кнопка «📊 История» в главном меню.
  - Графики прогресса (вес/тоннаж).
  - Кнопка «Обновить шаблон» (перенос фактических весов в план).
- **C2.5 (Тесты):** Внедрение `pytest` для тестирования логики сервисов.
- **C3 (Инфраструктура):** Миграции Alembic, деплой на VPS (systemd/Docker).
- **C4 (Web-панель и Админка):** FastAPI, авторизация через Telegram, графики на большом экране, **Web App для ввода чисел** прямо в чате, админ-панель для просмотра пользователей и рассылок.
- ## 6. Инфраструктура и мониторинг (после C4)
- **UptimeRobot:** Внешний пинг сервера каждые 5 минут с алертом в Telegram при падении.
- **Grafana + Prometheus:** Визуализация нагрузки (CPU/RAM/сеть), красивые дашборды.
- **n8n:** Автоматизация бизнес-процессов (например, если бот не отвечает 10 минут -> перезапустить контейнер и уведомить админа).
