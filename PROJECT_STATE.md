# 🏋️ Workout Bot — Состояние проекта (Бортовой журнал)

## 1. Стек и архитектура
- **Язык:** Python 3.12
- **Фреймворк:** aiogram 3.x
- **БД:** PostgreSQL + SQLAlchemy 2.0 (asyncpg)
- **Архитектура:** Слой хэндлеров (aiogram), слой моделей (SQLAlchemy), слой запросов (`app/db/queries.py`).
- **Запуск:** Docker Compose (БД на порту 5433, чтобы не конфликтовать с локальным Postgres).
- **Виртуальное окружение:** `.venv`

## 2. Ключевые сущности (БД)
- `User` — пользователи (привязка по `tg_id`).
- `WorkoutType` — шаблоны тренировок. Имеет флаг `is_archived` (мягкое удаление).
- `Exercise` — упражнения в шаблоне. 
  - `kind`: `strength` (подходы/повторы), `warmup`/`cardio` (длительность). 
  - `weight_kg` — **СТРОКА** (String 32), чтобы писать «Своё тело», «Резинка».
  - Флаги `is_optional` (опциональное) и `is_archived`.
- `WorkoutSession` — факт выполнения тренировки (начало/конец).
- `SessionSet` — фактические подходы (снимок reps/weight на момент выполнения).
- `SessionExerciseNote` — **НОВАЯ** таблица. Заметка к конкретному упражнению в рамках конкретной сессии. Связь `(session_id, exercise_id)`.

## 3. Архитектурные решения и паттерны
- **Время и часовой пояс:** В БД храним UTC, на экран выводим в МСК (функции в `app/utils.py`).
- **Вес (строки):** Для парсинга и вывода используем `format_weight()` в `app/utils.py`. Тоннаж считается только если вес конвертируется во `float`, иначе пропускается.
- **Удаление и Архив:** Если у тренировки/упражнения есть история, она не удаляется, а архивируется (`is_archived = True`). 
- **Слияние дубликатов:** При восстановлении из архива, если есть активное упражнение с таким же именем И ТИПОМ (`kind`), история объединяется (`ex_restore_merge`), дубликат удаляется.
- **Сортировка:** В карточке упражнения есть кнопки ⬆️/⬇️ для изменения `sort_order`. В активной тренировке опциональные упражнения принудительно уезжают в конец (через `sorted` в `_render_list`).
- **Отмена (FSM):** Любой диалог кладет в `state` ключ `return_to` (например, `"ex_card"`, `"tr_strength_summary"`). Обработчик `/cancel` и кнопка `❌ Отмена` возвращают пользователя на нужный экран.
- **Умные подсказки (История):** 
  - Функция `get_last_completed_set` имеет параметр `current_session_id`. Мы передаем туда ID текущей сессии, чтобы «Предыдущая тренировка» показывала только *прошлые* сессии.
  - Заметки из прошлого показываются, только если они были в *последней* тренировке (исключая текущую).
  - Кнопка «✅ Как в прошлый раз» подстраивается под текущую тренировку (берет последний подход из текущей сессии, чтобы не сбивать ритм).

## 4. Текущий функционал (C1 — Готово)
- Полный CRUD тренировок и упражнений, сортировка, архивация и слияние дубликатов.
- Поддержка текстового веса.
- Заметки к упражнениям (на экране подхода и экране итогов).
- Умный расчет прогресса: опциональные не портят статистику.
- Процесс тренировки: кардио (время) и силовые (подходы), редактирование выполненных подходов, добавление сверх плана.
- Warning при завершении, если есть невыполненные упражнения.
