# 🏋️ Workout Bot — Состояние проекта (Бортовой журнал)

## 1. Стек и архитектура
- **Язык:** Python 3.12
- **Фреймворк:** aiogram 3.x
- **БД:** PostgreSQL + SQLAlchemy 2.0 (asyncpg)
- **Архитектура:** 
  - `handlers/` — только прием событий и вызов сервисов (разбиты по зонам ответственности).
  - `services/` — бизнес-логика и запросы к БД (`training_service`, `navigation_service`).
  - `db/` — модели и базовые сессии.
- **Запуск:** Docker Compose (БД на порту 5433), `python bot.py`.

## 2. Ключевые сущности (БД)
- `User` — пользователи.
- `WorkoutType` — шаблоны тренировок (флаг `is_archived`).
- `Exercise` — упражнения в шаблоне (`kind`: `strength` или `cardio`; текстовый `weight_kg`; `is_optional`; `is_archived`).
- `WorkoutSession` — факт выполнения.
- `SessionSet` — подходы (время, вес, повторы, `completed_at`).
- `SessionExerciseNote` — заметки к упражнению в конкретной сессии.

## 3. Архитектурные решения и паттерны
- **Рефакторинг:** Проведен глобальный рефакторинг. Файлов >500 строк нет. Логика разделена.
- **Опциональные упражнения:** Скрыты из основного списка. В активной тренировке доступны через кнопку «⚪ Опциональные (X)». Не портят прогресс, если их не делать.
- **Таймеры:** Используется `asyncio.Task` и глобальный словарь `ACTIVE_TIMERS` в `training_service.py`. 
- **Отмена:** Централизована в `navigation_service.resolve_cancel_view()` (возвращает на нужный экран).
- **Удаление/Архив:** Удаление подходов разрешено только для «дополнительных» (сверх плана). Работа с архивами (слияние дублей, восстановление) вынесена в `workout_archive.py`.
- **Умные подсказки:** Игнорируют текущую сессию (показывают только прошлые).

## 4. Текущий статус (Перед тестом в зале)
- **C1 полностью готов.** Весь базовый функционал тренировок, справочника, таймеров и заметок работает.
- Все известные критические баги (MissingGreenlet, конфликты импортов, таймеры) исправлены.

## 5. Roadmap (Что дальше)
- **СЕЙЧАС:** Полевой тест в зале (сбор обратной связи и багов).
- **C2:** История тренировок (`/history`), Прогресс (сравнение с прошлой тренировкой), Графики.
- - **Кнопка «Сделать планом»:** На экране итогов упражнения добавить кнопку, которая переносит фактические веса/повторения в шаблон (справочник), чтобы план не отставал от реальности.
- **Отображение плана и истории:** Если план в шаблон отличается от последнего выполненного подхода, выводить их оба на экран (например, «Прошлый раз: 100 кг / План: 50 кг»), чтобы пользователь понимал разницу.
- **C2.5:** Внедрение автотестов (`pytest`).
- **C3:** Миграции Alembic, Деплой на VPS.
- **C4:** Веб-панель и Админка (FastAPI).
- - **Умный таймер через Telegram Web App:** Создать мини-приложение для таймера, чтобы он работал прямо в клиенте Telegram (не зависел от потери сети и работал даже при закрытом чате).
