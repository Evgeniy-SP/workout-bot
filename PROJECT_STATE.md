# 🏋️ Workout Bot — Состояние проекта (Бортовой журнал)

## 1. Стек и архитектура
- **Язык:** Python 3.12
- **Фреймворк:** aiogram 3.x
- **БД:** PostgreSQL + SQLAlchemy 2.0 (asyncpg)
- **Архитектура:** Слой хэндлеров (aiogram), слой моделей (SQLAlchemy), слой запросов (`app/db/queries.py`).
- **Запуск:** Docker Compose (БД на порту 5433, чтобы не конфликтовать с локальным Postgres).
- **Виртуальное окружение:** `.venv`

## 2. Ключевые сущности (БД)
- `User` — пользователи (привязка по `tg_id`).
- `WorkoutType` — шаблоны тренировок. Имеет флаг `is_archived` (мягкое удаление).
- `Exercise` — упражнения в шаблоне. 
  - `kind`: `strength` (подходы/повторы), `warmup`/`cardio` (длительность). 
  - `weight_kg` — **СТРОКА** (String 32), чтобы писать «Своё тело», «Резинка».
  - Флаги `is_optional` (опциональное) и `is_archived`.
- `WorkoutSession` — факт выполнения тренировки (начало/конец).
- `SessionSet` — фактические подходы (снимок reps/weight/время на момент выполнения, `completed_at`).
- `SessionExerciseNote` — заметка к конкретному упражнению в рамках конкретной сессии.

## 3. Архитектурные решения и паттерны
- **Время и часовой пояс:** В БД храним UTC, на экран выводим в МСК (функции в `app/utils.py`).
- **Вес (строки):** Используем `format_weight()` для парсинга и вывода. Тоннаж считается только для чисел.
- **Удаление и Архив:** Если у тренировки/упражнения есть история, она архивируется (`is_archived = True`). Физическое удаление из архива каскадно удаляет историю (с предупреждением).
- **Слияние дубликатов:** При восстановлении из архива бот проверяет совпадения по имени и типу (`kind`). Если находит — предлагает «Объединить и восстановить», перенося подходы и заметки на активную сущность.
- **Сортировка:** В карточке упражнения кнопки ⬆️/⬇️ меняют `sort_order`. При каждом перемещении список нормализуется (0, 1, 2...). В активной тренировке опциональные упражнения принудительно уезжают в конец списка.
- **Отмена (FSM):** Любой диалог кладет в `state` ключ `return_to`. `/cancel` и кнопка `❌ Отмена` возвращают на нужный экран.
- **Умные подсказки:** `get_last_completed_set` ищет данные в *прошлых* сессиях, исключая текущую.
- **Таймеры отдыха:** Используется фоновый `asyncio.Task`, хранящийся в глобальном словаре `ACTIVE_TIMERS`. Есть автоочистка сообщений через 15 секунд.

## 4. Текущий функционал (C1 — ПОЛНОСТЬЮ ГОТОВ)
- Полный CRUD тренировок и упражнений, сортировка, архивация и слияние дубликатов (с предупреждением при создании).
- Поддержка текстового веса.
- Заметки к упражнениям (на экране подхода и экране итогов).
- Умный расчет прогресса (опциональные не портят статистику, если их не делали).
- Процесс тренировки (кардио/силовые), редактирование выполненных подходов.
- Таймеры отдыха (60с, 90с, своё время) с фоновыми уведомлениями и корректным обновлением клавиатуры.
- Проверка на пустой список упражнений при старте.
- Warning при завершении, если есть невыполненные упражнения.

## 5. Roadmap (Что дальше)
- **Рефакторинг (Текущий шаг):** Разбивка `training.py` на 5-6 логических файлов, вынос сервисных функций в `training_service.py`.
- **C2:** История (`/history`), Прогресс (сравнение с прошлой тренировкой, графики), Reply-клавиатура, Постоянные памятки к упражнениям (notes в Exercise).
- **C3:** Миграции Alembic (вместо `init_db()`), Деплой на VPS.
- **C4 (Глобальная цель): Веб-панель и Админка.**
  - **Стек:** FastAPI + Jinja2/React.
  - **Функции:** Графики прогресса, удобное редактирование с ПК, экспорт в CSV, статистика активности и управление пользователями для админа.
  - **Авторизация:** Вход через Telegram Login Widget.
